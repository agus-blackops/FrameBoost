  [bedrock-samples](https://github.com/Mojang/bedrock-samples) `version.json`.
- Mojang's module metadata for 1.26.50 includes `@minecraft/server` **2.10.0**
  and `@minecraft/server-ui` **2.2.0** as stable versions. Those are the npm
  typings this project compiles against, and the tests enforce that the manifest

  filter, and the `nearest_attackable_target` / `melee_attack` /

Validator findings left as they are, and why:

- *`uv_anim` missing in the render controllers*: vanilla render controllers
  (for example `controller.render.zombie`) omit it too. It is optional in the
  game.
- *`item_texture.json` textures is a string, array required*: vanilla
  `item_texture.json` uses strings throughout.
- *Recipe links to `minecraft:paper` / `minecraft:stick` not found in this
  pack*: they are vanilla items.
- *Format versions lower than 1.26.50*: entity 1.26.0, item 1.26.30 and recipe
  1.20.10 are the versions vanilla 1.26.50 itself ships for these file types.
  Client entities stay on the long-standing 1.10.0 schema. These are
  recommendations, not errors. The animation file was raised to 1.10.0 as
  recommended.

## Manual in-game testing

Run the 24-step checklist in [TESTING.md](../TESTING.md) on Windows or Android
first, then the controller and touch passes. Top risks to confirm in-game:

1. Units path to the rally marker (the move mechanism depends on targeting a
   custom, invulnerable entity).
2. The tunic colour switches through `query.property('aoc:faction')` in the
   render controller.
3. `variable.attack_time` drives the attack swing on a custom entity. If not,
   units still fight; only the swing animation is missing.
4. The Commander Map's `onUse` fires from the touch "use" gesture on Android.

## Known limitations

- Units only act in loaded chunks. Orders reach 48 blocks, and units out of
  range of their commander are skipped and reported.
- Units fighting a monster when ordered to move may finish that fight first.
- After an order, arrived units stand clustered around one point. Formations
  are Milestone 3.
- Move orders are not saved. A reload leaves units idle, with the rally markers
  removed.
- Eight simultaneous move orders world-wide (one per channel).
- Unit counts for caps live in the save. If a unit disappears without dying
  (for example, removed by another add-on), run `/aoc:debug recount` near your
  units.
- Player identity is `Player.id`. It is assumed stable per player per world;
  verify across platforms in Milestone 6.
- Only wood is gatherable. Food, stone and gold already exist in the save format.
- Console distribution goes through a Realm or a hosted world. The Realm route
  is documented but unverified ([PLATFORMS.md](../PLATFORMS.md)).
- Nothing is measured yet on Series S or Android performance; see the
  procedure in TESTING.md.
